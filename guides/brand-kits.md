# Build a brand world

For new websites and apps, build the brand kit **before** generating any UI mockup. First ask about the site and tone and present reference choices. Research real font candidates, make an editable logo, generate product or editorial imagery, and compose an HTML kit that imports the selected fonts. Inspect the rendered result and attach its screenshot to subsequent mockup generation. See the complete brand-first workflow (see the companion guidance site) and the separate marketing/product briefs (see the companion guidance site).

A brand kit makes one visual idea useful across several applications. It should carry consistent decisions about silhouette, color, type and imagery rather than repeating one picture everywhere.

## Deliver a composed brand board

The primary deliverable is a styled, unified presentation with a generated logo, live wordmark, real imported font specimens, coordinated imagery and labeled palette swatches all visible together in an actual screenshot. Design the board to express the brand's tone. Large imagery, considered overlap or framing, deliberate typography and color relationships should make the identity understandable at a glance. A plain specimen sheet, a documentation page, separate image cards, or raw CSS beside a few thumbnails is insufficient.

Generate the logo when requested; do not replace that step with an emoji, stock icon or improvised generic SVG symbol. Keep the original generated mark and its prompt. Use live typography for exact brand lettering. A vector adaptation is a separate deliverable and must not be misrepresented as the generated original.

Compose with HTML and imported fonts, inspect the rendered board, and save a screenshot containing every part together. Confirm actual fonts, logo and images have loaded before capture. Provide both the composed screenshot and editable HTML. Put font research, histogram details, prompts, CSS tokens and copy controls in companion details outside the captured presentation. Attach this reviewed screenshot to subsequent UI mockup generation.

## Separate concept art from production assets

| Deliverable | Useful tool | What to verify |
|---|---|---|
| Art direction board | Image generation | Coherence and hierarchy |
| Wordmark | Live type or vector editor | Lettering, spacing, scale |
| Symbol | Editable vector construction | Small-size clarity and shape consistency |
| Color tokens | CSS custom properties | Real text/background contrast |
| Applications | HTML/CSS or layout tool | Actual content and usable dimensions |

Do not trace every artifact of an image-generated mark. If an exact logo is supplied, use that asset and protect its colors. Grade imagery before placing exact brand elements.

## Ask for a usable handoff

> Translate the approved concept into editable production assets: a simple SVG symbol, a live-text wordmark, CSS custom properties, a typography specimen and an HTML application example. Identify any substitutions. Keep generated botanical art separate from the mark. Check the mark at 24 pixels, body text at 16 pixels and the full page at mobile width.
