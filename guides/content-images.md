# Fill the page with intention

A hero establishes a visual world. Supporting images should make that world useful: explain a feature, illustrate a story or give a project a recognizable thumbnail.

## Make an asset map first

When implementing a UI mockup, inventory the images pictured inside it and generate them as separate standalone outputs before using them in code. Attach the selected mockup for composition and the kit/original for treatment; exclude surrounding UI in each prompt. Never crop a screenshot into production artwork. Record every page/region-to-file mapping, prompt, raw output, dimensions and responsive crop. Previously generated kit images can be reused where they are the intended matching assets; new or changed pictures need fresh generation and inspection. See the page-by-page workflow (see the companion guidance site).

## A matched content prompt

> Use image-gen-soul and the original garden anchor. Create one square content illustration: a white magnolia above a mossy stone pool, with fern leaves and visible ripples. Preserve the anchor's painted leaf edges, quiet cream highlights and olive shadows. Use a tighter camera than the hero, without changing the material treatment. No text, border or logo. Deliver a single image that remains clear at thumbnail size.

## Keep a series from drifting

Return to the approved original anchor for every new asset. Keep a short series contract: edge behavior, light direction, palette relationships and material treatment. Permit viewpoint, object and framing to vary when the content requires it.

Do not copy the previous derivative's accidental artifacts into the next request. Consistency comes from stable decisions, not from repeating identical color-correction numbers.

## Placeholder content that tells the truth

AI-generated imagery can make a draft feel complete while real photography is being commissioned. Label fictional brands and concept work clearly. Do not fabricate customer photos, testimonials, results or product evidence. Use descriptive alternative text based on what the image actually shows.

The three brands on this site are fictional demonstrations. Their small tools work locally, and they make no real reservations or enquiries. Replace the image and its alt text together when production assets arrive.

## Ask for the whole page

> Build the page in semantic HTML and CSS. Map each image to one section before generating. Keep headings, labels and calls to action live. Generate only the supporting assets needed to communicate the content. Record prompt, source reference, dimensions, alt text, palette and grade decision for each file. Use a framework-neutral asset manifest and CSS custom properties.
